# 🗄️ Database Schema Documentation

## Overview
This document describes the complete database schema for the **FedEx Debt Collection Management Platform**. The system supports a 3-tier role-based access control system with automatic organization assignment and comprehensive audit trails.

---

## 🔐 Authentication & Role System

### User Roles
The system supports three distinct user roles with hierarchical permissions:

| Role | Database Enum | Description | Access Level |
|------|---------------|-------------|--------------|
| **FedEx Administrator** | `FEDEX_ADMIN` | Top-level platform administrators | Can view/manage ALL cases across all organizations |
| **Agency Manager** | `DCA_MANAGER` | Middle management at debt collection agencies | Can view/manage cases within their organization |
| **Agency Agent** | `DCA_AGENT` | Front-line agents at debt collection agencies | Can view/update cases within their organization |

### Organization Assignment Logic
When users sign up, the system automatically assigns roles and organizations based on their selection:

```sql
-- Trigger Function Logic
CASE 
    WHEN organization_type = 'FedEx Administrator' THEN 'FEDEX_ADMIN' + 'FEDEX_HQ'
    WHEN organization_type = 'Agency Manager' THEN 'DCA_MANAGER' + 'DCA_8f3d1'
    WHEN organization_type = 'Agency Agent' THEN 'DCA_AGENT' + 'DCA_9a2b4'
    ELSE 'DCA_AGENT' + 'DCA_7c1d2' -- Fallback for edge cases
END
```

### Organization IDs (Fixed Constants)
| Organization ID | Purpose | Assigned To |
|----------------|---------|-------------|
| `FEDEX_HQ` | FedEx headquarters | All FedEx Administrators |
| `DCA_8f3d1` | Agency Manager organization | All Agency Managers |
| `DCA_9a2b4` | Agency Agent organization | All Agency Agents |
| `DCA_7c1d2` | Default/fallback organization | Edge cases and defaults |

## 📊 Database Tables

### 1. **profiles** Table
Links Supabase Auth users to business roles and organizations.

```sql
CREATE TABLE public.profiles (
  id UUID REFERENCES auth.users NOT NULL PRIMARY KEY,
  email TEXT,
  role user_role DEFAULT 'DCA_AGENT',
  organization_id TEXT,
  full_name TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT now()
);
```

| Column | Type | Purpose |
|--------|------|---------|
| `id` | UUID | Foreign key to `auth.users` |
| `email` | TEXT | User's email address |
| `role` | ENUM | One of: FEDEX_ADMIN, DCA_MANAGER, DCA_AGENT |
| `organization_id` | TEXT | Organization identifier (FEDEX_HQ, DCA_8f3d1, etc.) |
| `full_name` | TEXT | User's display name |
| `created_at` | TIMESTAMP | Account creation timestamp |

### 2. **cases** Table
Main table storing all debt collection cases with comprehensive tracking.

```sql
CREATE TABLE public.cases (
  -- Identifiers
  case_id TEXT PRIMARY KEY,
  customer_id TEXT, 
  customer_name TEXT,
  
  -- Financial Data
  invoice_amount NUMERIC,
  amount_recovered NUMERIC DEFAULT 0,
  days_overdue INT,
  case_status case_status_enum DEFAULT 'OPEN',
  
  -- AI & Analytics
  risk_score FLOAT,
  priority_level priority_level_enum,
  predicted_recovery_date DATE,
  
  -- Assignment & Performance
  dca_id TEXT,
  dca_performance_score INT,
  assigned_date TIMESTAMP,
  
  -- Operations & Escalation
  sla_breach_count INT DEFAULT 0,
  escalation_flag BOOLEAN DEFAULT false,
  escalation_reason TEXT,
  last_action_date TIMESTAMP,
  next_followup_date TIMESTAMP,
  
  -- Audit
  created_at TIMESTAMP WITH TIME ZONE DEFAULT now(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT now()
);
```

#### Case Status Workflow
- **OPEN**: New case, no action taken
- **IN_PROGRESS**: Case being actively worked
- **PAID**: Customer has paid, case resolved
- **DISPUTE**: Customer disputes the debt

#### Priority Levels
- **HIGH**: Urgent cases requiring immediate attention
- **MEDIUM**: Standard priority cases  
- **LOW**: Lower priority cases

### 3. **case_actions** Table
Audit trail tracking all actions performed on cases.

```sql
CREATE TABLE public.case_actions (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  case_id TEXT REFERENCES public.cases(case_id),
  performed_by UUID REFERENCES auth.users(id),
  action_type TEXT, -- 'CALL', 'EMAIL', 'PROMISE_TO_PAY', etc.
  sentiment_score FLOAT, -- AI sentiment analysis
  note TEXT,
  created_at TIMESTAMP DEFAULT now()
);
```

## 🛡️ Row Level Security (RLS) Policies

### Case Access Policies

#### 1. FedEx Admin - Universal Access
```sql
CREATE POLICY "FedEx Admin View All"
ON public.cases FOR SELECT
USING (
  (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'FEDEX_ADMIN'
);
```
**Result**: FedEx Administrators can view ALL cases across all organizations.

#### 2. DCA Manager - Organization Scope
```sql
CREATE POLICY "DCA Manager View Organization Cases"
ON public.cases FOR SELECT
USING (
  (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'DCA_MANAGER'
  AND dca_id = (SELECT organization_id FROM public.profiles WHERE id = auth.uid())
);
```
**Result**: DCA Managers can only view cases assigned to their organization (DCA_8f3d1).

#### 3. DCA Agent - Organization Scope
```sql
CREATE POLICY "DCA Agent View Assigned Only"
ON public.cases FOR SELECT
USING (
  (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'DCA_AGENT'
  AND dca_id = (SELECT organization_id FROM public.profiles WHERE id = auth.uid())
);
```
**Result**: DCA Agents can only view cases assigned to their organization (DCA_9a2b4 or DCA_7c1d2).

### Modification Policies
Similar hierarchical policies exist for INSERT, UPDATE, and DELETE operations, ensuring users can only modify data within their access scope.

### Audit Trail Policies
- Users can insert case actions on cases they have access to
- Users can view case actions only for cases within their access scope
- All actions are permanently logged with user attribution

## 🔄 Trigger Functions

### User Signup Handler
```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO public.profiles (id, email, role, organization_id, full_name)
    VALUES (
        new.id,
        new.email,
        CASE 
            WHEN new.raw_user_meta_data->>'organization_type' = 'FedEx Administrator' THEN 'FEDEX_ADMIN'::user_role
            WHEN new.raw_user_meta_data->>'organization_type' = 'Agency Manager' THEN 'DCA_MANAGER'::user_role
            WHEN new.raw_user_meta_data->>'organization_type' = 'Agency Agent' THEN 'DCA_AGENT'::user_role
            ELSE 'DCA_AGENT'::user_role
        END,
        CASE 
            WHEN new.raw_user_meta_data->>'organization_type' = 'FedEx Administrator' THEN 'FEDEX_HQ'
            WHEN new.raw_user_meta_data->>'organization_type' = 'Agency Manager' THEN 'DCA_8f3d1'
            WHEN new.raw_user_meta_data->>'organization_type' = 'Agency Agent' THEN 'DCA_9a2b4'
            ELSE 'DCA_7c1d2'
        END,
        COALESCE(new.raw_user_meta_data->>'full_name', split_part(new.email, '@', 1))
    );
    RETURN new;
END;
$$;
```

**Purpose**: Automatically creates a profile with appropriate role and organization when a user signs up.

### Updated At Trigger
```sql
CREATE TRIGGER handle_cases_updated_at BEFORE UPDATE ON public.cases
    FOR EACH ROW EXECUTE PROCEDURE public.handle_updated_at();
```
**Purpose**: Automatically updates the `updated_at` timestamp when case records are modified.

## 🔒 Security Features

1. **Row Level Security**: Enforced at the database level, preventing unauthorized data access
2. **Role-based Access Control**: Hierarchical permissions based on business roles
3. **Audit Trail**: Complete tracking of all user actions with attribution
4. **Data Isolation**: Organizations can only access their assigned cases
5. **Automatic Assignment**: Prevents manual role/organization manipulation
6. **Trigger Protection**: Database-level enforcement of business rules
